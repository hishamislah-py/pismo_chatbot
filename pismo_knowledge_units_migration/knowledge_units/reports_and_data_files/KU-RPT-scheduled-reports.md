# Data and reporting overview

The Pismo platform's event-driven architecture manages the data events that occur during the course of normal processing. **Data events** include account actions, transactions, payments, auditing, and so on. This provides you with comprehensive and timely information for reporting and analytics and also give you the ability to monitor product success, create metrics, send notifications, and generate business intelligence.

Pismo generates two types of events:

* **Data events** — Event notifications and data delivered in real-time (streaming event delivery) or periodically via file transfer (batch file event delivery) to your cloud storage. These events are built in to the Pismo platform and do not require client definition like account timeline events. Similar to timeline events though, many of the data events also pertain to account activity. For more information, refer to [Data events](https://developers.pismo.io/pismo-docs/docs/event-data) and, for information about APIs and the events they generate, refer to  [Event-generating APIs](https://developers.pismo.io/pismo-docs/docs/data-events).
* **Timeline events** — Events that occur over an account's life cycle and are directed toward your end user. These constitute a separate event system to data events and do not require cloud storage. You need to work with your Pismo representative to define and set this up. For more information, refer to the [Timeline events overview](https://developers.pismo.io/pismo-docs/docs/timeline-overview).

> 📘 Timeline events versus data events
>
> [Timeline events](https://developers.pismo.io/pismo-docs/docs/timeline-overview) are meant to deliver messages to your end users, such as a credit-limit notification in a mobile banking app. These are not the same as [data events](https://developers.pismo.io/pismo-docs/docs/event-data).

# Scheduled reports

Pismo can run batch jobs to generate report files. There are two types of scheduled report files available.

* [Base scheduled reports](https://developers.pismo.io/pismo-docs/docs/base-scheduled-reports): General information about the performance of your programs
* [Regulatory scheduled reports](https://developers.pismo.io/pismo-docs/docs/regulatory-scheduled-reports): Information that you might need to provide to regulatory agencies

Report files are written to your organization's dedicated S3 bucket. To start receiving report files, contact your Pismo representative to configure access to your S3 bucket.

> 📘
>
> Most Pismo customers use Amazon Web Services (AWS) S3 buckets as their cloud storage containers, so this section assumes you're using AWS. However, Pismo does support other cloud services, such as Google Cloud Platform (GCP) and Microsoft Azure. Contact your Pismo representative for information about using a cloud service other than AWS.

The jobs that generate report files all run once a day at 5:00 AM UTC. When a job executes, it searches for records that meet filter conditions. If any are found, it writes the data to a file that it creates in your cloud storage container. Files are saved in [Parquet](https://aws.amazon.com/about-aws/whats-new/2018/12/amazon-s3-announces-parquet-output-format-for-inventory/) format.

> 📘
>
> In most cases, a report file is not generated if no records are found that match the filter conditions.

Files are written and saved according to type (daily, monthly, or full) and date. The full type is explained below. The URL takes the form `[path to S3 bucket]/reports/[job_name]/[type]/[date values]/[filename].parquet`, where \[filename] represents a [Spark hash](https://kontext.tech/article/1053/spark-hash-functions-introduction-md5-and-sha).

For example:\
`s3://pismo-dataplatform-tn -55317847-57cd-45a3-8aed-a8dadd63cc6b/reports/accounting_events/type=daily/year=2020/month=1/day=10/[filename].parquet`\
In this example, the value for `job_name` is `accounting_events`. You can find the value for `job_name` in the documentation for the specific report file.

Files and paths are generated on the following basis:

* **Daily:**  In this case, the type is `daily` and the date partitioning values are `/year=YYYY/month=MM/day=DD/ `. For example,  `.../reports/accounting_events/daily/2020/1/10/[filename].parquet`

* **Monthly:** At your request, or when there is a need for periodic reprocessing, a job executes for a closed month of data. In this case, the type is `monthly` and the date partitioning is ` year=YYYY/month=MM`. For example,  `.../reports/accounting_events/type=monthly/year=2020/month=1/[filename].parquet`

* **Full:** You can generate a complete file, taking into account all past job data without a date filter. In this case, the type is  `full` and the partitioning corresponds to the file's generation date. For example: `.../reports/accounting_events/type=full/year=2020/month=1/day=10/[filename].parquet`

> 🚧
>
> The date partition values in the report correspond to the last date when the data was available, not the date when the job was executed. For example, for a daily job that runs on March 11, the date partition values correspond to March 10.

# Base scheduled reports

**Base scheduled reports** are documents generated by the Pismo platform that provide information about the performance of your programs. Unlike [Regulatory scheduled reports](https://developers.pismo.io/pismo-docs/docs/regulatory-scheduled-reports), they are not formatted for submission to regulatory entities.

To start receiving report files, contact your Pismo representative.

# Available base scheduled reports

The following base scheduled reports are available.

* [Accounting events report files](https://developers.pismo.io/pismo-docs/docs/accounting-events-report-files)
* [Accounts analytic report files](https://developers.pismo.io/pismo-docs/docs/accounts-analytic-report-files)
* [Accounts balances report files](https://developers.pismo.io/pismo-docs/docs/accounts-balances-report-files)
* [Account limits report files](https://developers.pismo.io/pismo-docs/docs/account-limits-report-files-v2)

# Regulatory scheduled reports

**Regulatory scheduled reports** are documents that you must provide to regulatory entities such as central banks and government agencies in accordance with applicable laws and regulations.

For some jurisdictions, the Pismo platform can generate regulatory scheduled reports for you in the proper format and layout. The reports only include data available on the Pismo platform, so they don't include information generated outside of Pismo's systems. You need to supplement the reports with such data before transmitting them.

For more information about how to receive scheduled reports, refer to [Scheduled reports](https://developers.pismo.io/pismo-docs/docs/scheduled-reports).

> 📘
>
> Pismo can create regulatory scheduled reports for any country/locale, but only reports for Brazil and the United States are currently available. If you're located in another part of the world, and you want Pismo to generate your regulatory scheduled reports, contact your Pismo representative.

# Requesting regulatory scheduled reports

To request a regulatory scheduled report, open a ticket with [Pismo Service Desk](https://developers.pismo.io/pismo-docs/docs/service-desk). Your ticket must contain the following information.

* **Type:** Service Request
* **Description:** Include the <Glossary>Org</Glossary> IDs from your test (EXT) and production environments. Specify which reports you want to receive and the period (start date and end date) for each report. The regulator's rules determine how frequently the Pismo platform generates a report.
* **SLA for request fulfillment:** Up to 5 business days
